任务 1: ILA BURST_PTR 数据回读修复

进展和结果:

修复了 ILA force trigger 回读时 4096 个样本全部相同的 Bug。根因是 soft_ila_top_fcapz 的读地址计算中 data_sample = data_byte_off / (WORDS*4) 整数除法截断，改为扁平偏移编址后正常。

遇到的问题:

ILA wrapper 的 bram_rd_addr 是为 JTAG 突发读设计的，逐字读时 data_byte_off 始终在 0~11 范围变化，整数除法截断导致始终读同一 BRAM 行。

解决方法:

使用 FCAPZ_DATA_BASE + i * 20 + word_offset 扁平偏移，将样本索引直接编码到地址中。

任务 2: 硬件触发调试 — TRIG_MASK 默认值问题

进展和结果:

TRIG_MASK 寄存器上电默认值 = 全 1。testbench 只写了 word0 (bits 31:0)，word1/2 保持全 1。EQ 比较时高位总线信号非零 → 整个比较失败。显式清零所有 TRIG_MASK word 后硬件触发正常。

解决方法:


ila_write(FCAPZ_TRIG_MASK,     32'h0004_0000);   // word0
ila_write(FCAPZ_TRIG_MASK + 1, 32'h0);           // word1
ila_write(FCAPZ_TRIG_MASK + 2, 32'h0);           // word2
ila_write(FCAPZ_TRIG_MASK + 3, 32'h0);           // word3
ila_write(FCAPZ_TRIG_MASK_EXT,  32'h0);           // word4 (EXT 地址)

任务 6: ILA 标准模式重构

进展和结果:

将项目 ILA 集成从自定义模式 (sim_mod mux + 专用仿真端口) 重构为标准模式，严格遵循 fpga_ila 快速入门指南的三要素结构。仿真验证通过。

修改的文件:

rtl/webserver_cpu_top.v, sim/tb_fast.v

标准模式结构:


// ① 核总线 (多核共用 addr/wdata, 每核独立 we/re/rdata)
localparam ILA_NUM_CORES    = 1;
wire [ILA_NUM_CORES-1:0]     ila_we;
wire [ILA_NUM_CORES-1:0]     ila_re;
wire [15:0]                  ila_addr;
wire [31:0]                  ila_wdata;
wire [ILA_NUM_CORES*32-1:0]  ila_rdata;

// ② ILA 核 — 直连总线
soft_ila_top_fcapz #(...) u_ila_core0 (
    .reg_we        (ila_we[0]),
    .reg_re        (ila_re[0]),
    .reg_addr      (ila_addr),
    .reg_wdata     (ila_wdata),
    .reg_rdata     (ila_rdata[0*32 +: 32])
);

// ③ ILA Hub — 直连总线
ila_hub_top #(...) u_ila_debug (
    .core_reg_we    (ila_we),
    .core_reg_re    (ila_re),
    .core_reg_addr  (ila_addr),
    .core_reg_wdata (ila_wdata),
    .core_reg_rdata (ila_rdata)
);

ILA 标准模式使用问题总结

问题 1: 标准指南省略了 `reg_re` / `core_reg_re` 端口

快速入门指南的示例代码只显示了 .reg_we / .core_reg_we，没有 .reg_re / .core_reg_re。但实际 RTL 中这两个端口是 input/output 声明，无默认值，不连接会编译报错。

解决: 标准模式也必须连接 reg_re 和 core_reg_re:


soft_ila_top_fcapz:  .reg_re(ila_re[0])
ila_hub_top:         .core_reg_re(ila_re)

问题 2: Web GUI 加载 signals.json 无反应

Web GUI 的 _loadSignals() 函数只拷贝 name/probes 字段，漏掉 data_depth/num_probes。后续 _populateCoreSelect() 用 (c.data_depth || 0) > 0 过滤死核，导致刚加载的核被当作死核丢弃，页面静默无反应。

解决: 修改 index.html 的 _loadSignals()，完整拷贝 data_depth、num_probes、total_width、max_windows 等字段。

问题 3: Web GUI 默认波特率 115200 vs FPGA 921600

Web GUI 连接对话框默认波特率 115200，但标准模式下 ILA_BAUD = 921600。不匹配导致连接超时。

解决: 连接时手动改波特率为 921600，或修改 HTML 中默认值。

问题 4: 仿真中 testbench 如何访问 ILA 寄存器

标准模式下 Hub 直接驱动核总线，没有仿真 bypass 路径。testbench 需要通过 force 语句覆盖总线信号:


task ila_write(input [15:0] addr, input [31:0] data);
    @(posedge ila_clk);
    force dut.ila_we   = 1'b1;
    force dut.ila_addr = addr;
    force dut.ila_wdata = data;
    @(posedge ila_clk);
    force dut.ila_we   = 1'b0;
endtask

问题 5: 上板前必须确认 FPGA 已烧录

Web GUI 通过 UART 发送 fcapz 协议命令，需要 FPGA 上的 ILA Hub 响应。如果 FPGA 未烧录 bitstream，串口能打开但 Hub 不响应 → 连接超时。
