## 第一阶段: Ping 通网络 (ARP + ICMP)

### 任务 1: 搭建 iverilog 仿真环境 + 验证 RTL 硬件链路

**进展和结果:**


从零搭建 iverilog 仿真: xilinx_stubs (BUFG/IDDR/ODDR/IDELAYE2/xpm_memory), vendor_stubs (MMCM bypass), lcpu_bfm (固件加载), tb (GMII 帧注入)。仿真跑通: ARP Request 帧注入后全链路信号验证通过, gmii_rx_dv 拉高 → mac_rx_sop/eop 脉冲 → cpu_rd_empty 拉低。固件编译 2634 bytes, rv32ic, -O2, 0 error。

**遇到的问题:**


Xilinx 原语在 iverilog 中无法综合, 需要手写行为级 Stub。RGMII testbench 驱动时序错误: 在 IDDR 采样同一边沿驱动数据, 采样竞争导致 gmii_rx_dv 不拉高。RTL 模块内嵌 testbench 拖慢仿真。

**解决方法/经验总结:**


Stub 设计: BUFG 直通, IDDR posedge/negedge 分别采样, MMCM 时钟直通。RGMII 改为 opposite-edge 驱动: negedge 设低 nibble → posedge 采样; posedge 设高 nibble → negedge 采样。仿真证明 RTL 逻辑正确, 后续转上板。

**下一步计划:**


转入上板调试。

### 任务 2: 上板验证 RGMII → RX FIFO 链路 + 固件烧录

**进展和结果:**


上板烧录后 LED 流水灯正常 (确认 CPU 在跑)。PHY Link LED 亮, ping 时 Activity LED 闪烁。PC Wireshark 看到 ARP Request 发出 (问 169.254.1.1)。发现固件未嵌入 bitstream —— 指令 RAM 为空, CPU 无法执行。创建 update_and_program.sh, 用 updatemem 将 firmware.bin 嵌入 BRAM INIT。烧录 RiscV_WebSoC_fw.bit 成功。

**遇到的问题:**


固件未嵌入 bitstream: build.tcl 只生成纯 RTL bitstream, 指令 RAM BRAM INIT 是空的。Vivado 不在 PATH。

**解决方法/经验总结:**


updatemem 流程: firmware.bin → bank*.mem → updatemem → RiscV_WebSoC_fw.bit。FPGA 软核指令 RAM 初始值由 bitstream BRAM INIT 决定, 不是烧录后加载。

**下一步计划:**


固件已嵌入, 进行 ping 验证。

## 调试中发现的 Bug 及修复

### Bug 1: 栈指针未初始化 (严重)
文件 `c/main.c`, reset_entry。PicoRV32 上电 sp=0, 直接 j main 导致第一个函数调用写 0xFFFFFFFC 跑飞。  
修复: reset_entry 加 `la sp, _stack_top`。

### Bug 2: .bss 段未清零
文件 `c/main.c`, reset_entry。绕过 picolibc CRT, 静态变量初值不确定。  
修复: 加 bss 清零循环。

### Bug 3: 仿真上电延时过长
文件 `c/main.c`, program_main。5M 次延时循环在 iverilog 中耗时 3 秒, 仿真永远到不了主循环。  
修复: `#define SIM_FAST` + `#ifndef SIM_FAST`。

### Bug 4: BFM 复位释放卡死
文件 `sim/lcpu_bfm.v`。timer 变量在 delay 和 OP_DONE 间复用导致 RISC-V 复位永久拉低。  
修复: delay_timer 和 op_timer 分离。

### Bug 5: RGMII IDDR 采样竞争
文件 `sim/tb.v`。testbench 在 rgmii_rxc 同边沿驱动 rgmii_rxd, IDDR 采样到旧值。  
修复: opposite-edge 驱动。

## 第二阶段: TCP 三次握手

### 任务 6: 学习 TCP 协议基础

**进展和结果:**


TCP 报文格式: 固定头 20 字节, SrcPort(2)+DstPort(2)+SEQ(4)+ACK_Num(4)+DataOffset(4bit)+Flags(9bit)+Window(2)+Checksum(2)+Urgent(2)。六个 Flag: FIN(0x01) SYN(0x02) RST(0x04) PSH(0x08) ACK(0x10) URG(0x20)。TCP 校验和需 12 字节伪首部 (SrcIP+DstIP+Zero+Proto+TCP_Length), 覆盖伪首部+TCP头+Payload。三次握手: PC SYN(SEQ=x) → FPGA SYN+ACK(SEQ=y,ACK=x+1) → PC ACK(SEQ=x+1,ACK=y+1)。关键: SYN 和 FIN 各占一个序号, ACK_Num = 对方SEQ+1。状态机: CLOSED→LISTEN→SYN_RECEIVED→ESTABLISHED。连接表用并行数组, 避结构体偏移。详细笔记见 [TCP协议基础学习笔记](TCP协议基础学习笔记.html)。

**遇到的问题:**


无。

**解决方法/经验总结:**


TCP 校验和伪首部是虚拟的不实际发送, 与 IP/ICMP 校验和的关键区别。项目现有 cks_sum_cal() 可复用。
